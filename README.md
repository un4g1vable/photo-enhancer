# 🎨 Улучшение изображений в реальном времени — ML-модель в браузере

Веб-приложение, которое автоматически улучшает фотографии по **яркости, контрастности и цветности**. Нейросеть анализирует изображение и подбирает оптимальные параметры коррекции, а быстрый алгоритм применяет их к снимку — **полностью в браузере пользователя, без отправки данных на сервер**.

## О проекте

Курсовой проект на тему «Разработка системы улучшения изображений в реальном времени посредством запуска ML-модели в браузере пользователя».

Ключевая идея — **разделить «интеллект» и «исполнение»**. Вместо тяжёлой нейросети, которая перерисовывала бы изображение целиком (десятки мегабайт, медленно), используется лёгкая модель, которая лишь **анализирует** кадр и предсказывает **три числа** — коэффициенты коррекции яркости, контраста и насыщенности. Само применение этих коэффициентов к полному изображению выполняет простой и быстрый алгоритм на стороне браузера.

Такой подход даёт компактную модель (≈1.15 МБ), высокую скорость даже без видеокарты, экономию памяти и процессора — и полностью локальную обработку: изображения не покидают устройство пользователя.

## Возможности

- **Форматы:** JPG, PNG, BMP, HEIC (HEIC декодируется в браузере; декодер подгружается лениво — только при необходимости).
- **Размеры:** обработка изображений до 15 Мпк; более крупные автоматически уменьшаются до 15 Мпк, поэтому результат гарантирован для любого снимка.
- **Асинхронность:** весь конвейер выполняется в Web Worker — интерфейс не зависает даже на больших изображениях.
- **Производительность:** применение коррекции на GPU (WebGL-шейдер) с резервом на CPU — быстро и экономно по ресурсам.
- **Удобство:** загрузка перетаскиванием или выбором файла, очередь задач с прогрессом и отменой, сравнение «до/после», показ подобранных коэффициентов, скачивание результата.
- **Приватность:** обработка локальная, без сервера.

## Как пользоваться

1. Откройте приложение (демо-ссылку или локальный запуск).
2. Перетащите одно или несколько изображений в окно — или нажмите, чтобы выбрать файлы.
3. Дождитесь обработки: статус и прогресс отображаются на карточке задачи.
4. Сравните результат с оригиналом ползунком и нажмите **Скачать**.

## Как устроено решение

Обработка одного изображения проходит по конвейеру, целиком вынесенному в **Web Worker**, чтобы не блокировать интерфейс:

1. **Получение задачи.** Пользователь передаёт файл через API; задаче присваивается идентификатор.
2. **Декодирование.** Изображение открывается через `createImageBitmap` (HEIC предварительно конвертируется). Если размер превышает 15 Мпк — изображение пропорционально уменьшается.
3. **Анализ моделью.** Уменьшенная до 224×224 копия подаётся в модель TensorFlow.js; та возвращает три логарифма коэффициентов восстановления, которые переводятся в множители и ограничиваются безопасным диапазоном.
4. **Применение коррекции.** К изображению в полном разрешении применяются коэффициенты. Основной путь — **WebGL-шейдер** (один проход по GPU, миллисекунды даже на 15 Мпк); если WebGL недоступен — резервный расчёт на CPU по чанкам.
5. **Кодирование и выдача.** Результат кодируется (JPEG/PNG) и возвращается в виде готового изображения.

На каждом шаге воркер сообщает статус и прогресс — интерфейс обновляется через события.

### Математика коррекции

Формулы применения намеренно **совпадают с теми, на которых обучалась модель**, иначе предсказанные коэффициенты не восстановили бы изображение корректно:

1. яркость — умножение каналов на коэффициент;
2. контраст — растяжение значений относительно **средней яркости кадра** (а не фиксированной середины), благодаря чему контраст не сдвигает общую яркость;
3. насыщенность — смешивание цвета с его яркостной (серой) версией.

### API модуля обработки

Реализован программный интерфейс задач (по техническому заданию):

| Метод / событие | Назначение |
|---|---|
| `createTask(file) → id` | Поставить изображение на обработку, получить идентификатор задачи |
| `getStatus(id) → { status, progress, coefficients }` | Текущий статус и прогресс выполнения |
| `abort(id) → { ok }` | Прервать выполнение задачи |
| `getResult(id) → Blob` | Получить готовое изображение |
| событие `change` | Возникает при изменении статуса/прогресса; содержит актуальное состояние задачи |

Статусы задачи: `queued → decoding → analyzing → applying → encoding → done` (и `error` / `aborted`).

## Машинное обучение: как создавалась модель

Модель обучалась отдельно (Google Colab, TensorFlow/Keras) и экспортировалась в TensorFlow.js. Ниже — краткий отчёт о проделанной работе.

### Данные

Использован датасет **MIT-Adobe FiveK** — 5000 профессионально обработанных фотографий (версия эксперта `a`). Это эталоны «как должно быть». Готового набора «плохое фото → нужные коэффициенты» не существует, поэтому применён приём **самообучения на синтетических искажениях**: каждое эталонное фото случайно ухудшается по яркости/контрасту/насыщенности, а целью обучения становятся **обратные** коэффициенты, возвращающие фото к эталону.

### Разведочный анализ (EDA)

Измерены распределения яркости, контраста и насыщенности эталонов. Это задаёт «эталонную норму», к которой модель будет приводить изображения.

### Сравнение семейств моделей

Чтобы обосновать выбор архитектуры, проведено сравнение нескольких семейств на одной задаче: классические модели (линейная регрессия, случайный лес, градиентный бустинг, MLP) на усреднённых признаках изображения — против свёрточной нейросети, анализирующей изображение целиком.

<img width="1258" height="332" alt="image" src="https://github.com/user-attachments/assets/e96941e0-41fe-4dc6-81d7-2669cf8ba587" />

Вывод: модели на усреднённых признаках упираются в общий «потолок» точности (по нескольким числам коррекцию точнее не вывести), а свёрточная сеть, используя содержание кадра, заметно снижает ошибку — особенно по насыщенности. Поэтому в качестве итоговой выбрана компактная свёрточная сеть.

### Архитектура модели

Компактная **остаточная свёрточная сеть** на разделимых (separable) свёртках с дополнительной ветвью глобальных статистик изображения. Свёрточная часть отвечает за содержание кадра, ветвь статистик — за абсолютные уровни яркости/контраста/насыщенности. Итоговый размер модели — **≈1.15 МБ**.

## Результаты

| Метрика | Значение |
|---|---|
| Средняя ошибка коэффициентов (MAE, валидация) | ≈ **0.108** (лучшая модель на признаках — 0.137) |
| PSNR восстановленного изображения | **≈ 29.2 дБ** (ухудшённого — 24.9 дБ) |
| SSIM восстановленного изображения | **≈ 0.97** (ухудшённого — 0.93) |
| Размер модели | ≈ 1.15 МБ |

## Соответствие требованиям

| Требование ТЗ | Реализация |
|---|---|
| Работа во всех современных браузерах | Стандартные веб-API (Web Worker, WebGL, TensorFlow.js) |
| Суммарный объём кода ≤ 10 МБ | Модель ≈1.15 МБ + компактный код; укладываемся с запасом |
| Обработка изображений до 15 Мпк | Поддерживается; более крупные автоматически уменьшаются |
| Максимальное время обработки ≤ 30 с | Применение на GPU — миллисекунды даже на 15 Мпк |
| Среднее время обработки ≈ 5 с | Достигается за счёт уменьшенного входа модели и GPU-коррекции |
| Форматы JPG, PNG, HEIC, BMP | Поддерживаются (HEIC — через ленивый декодер) |
| Асинхронная работа без блокировки | Весь конвейер вынесен в Web Worker |
| API: постановка / статус / прерывание / получение результата | `createTask` / `getStatus` / `abort` / `getResult` |
| Событие изменения статуса задачи | Событие `change` с идентификатором, статусом и прогрессом |

## Технологии

- **Интерфейс и логика:** JavaScript (ES-модули), Vite, без фреймворков.
- **ML в браузере:** TensorFlow.js (GraphModel).
- **Обработка:** Web Worker, WebGL, Canvas / OffscreenCanvas, `createImageBitmap`.
- **Форматы:** нативное декодирование браузера (JPG/PNG/BMP) + ленивый декодер HEIC.
- **Обучение модели:** Python, TensorFlow / Keras, Google Colab; датасет MIT-Adobe FiveK.

## Структура проекта

```
public/model/            модель TensorFlow.js (model.json + веса + конфиг)
src/
  api/enhancer.js        публичный API задач (createTask/getStatus/abort/getResult + события)
  worker/
    pipeline.worker.js   конвейер обработки в Web Worker
    model.js             загрузка модели и предсказание коэффициентов
    decode.js            декодирование и приведение к ≤15 Мпк
    apply-gl.js          применение коррекции на GPU (WebGL)
    apply-cpu.js         резервное применение на CPU
  core/status.js         статусы задач и константы
  core/heic.js           ленивое декодирование HEIC
  ui/compare.js          компонент сравнения «до/после»
  main.js                интерфейс
  styles.css             стили
```
